Source of truth: `web/node_modules/next/dist/docs/` (bundled docs, v16.3.8). Paths below are relative to `docs/01-app/`.
Installed: `next@16.3.8`, `react@19.2.8` (App Router actually runs Next's bundled React canary), `@types/react@19.3.0`, Tailwind v4, ESLint 9 flat config. Project uses `src/app/`.

## 0. The one decision that changes everything: `cacheComponents`

Next 16 ships **two caching models**. Pick one per project; APIs differ.

| | Previous model (default, `cacheComponents` off) | Cache Components (`cacheComponents: true`) |
|---|---|---|
| Static by default? | Yes, unless Request-time API / uncached fetch after one | Data is **dynamic by default**; you opt in with `'use cache'` |
| Time-based ISR | `export const revalidate = 86400` | `'use cache'` + `cacheLife('days')` |
| `export const dynamic/revalidate/fetchCache/dynamicParams` | Supported | **Build error** ("not compatible with `nextConfig.cacheComponents`") |
| `generateStaticParams` returning `[]` | OK (all paths on first visit) | **Build error** `empty-generate-static-params`; must return >= 1 |
| `new Date()`, `Math.random()` in render | Frozen into prerender **[inf]** | **Build error** unless inside `'use cache'` or after `await io()`/`connection()` + `<Suspense>` |
| Unknown params | `dynamicParams` true/false | App Shell + background upgrade (needs `partialPrefetching: true` for full ISR) |
| Route nav | Unmount on navigate | React `<Activity hidden>`: **state persists across navigations** |
| Guides | `02-guides/caching-without-cache-components.md`, `02-guides/incremental-static-regeneration.md` | `01-getting-started/08-caching.md`, `09-revalidating.md`, `02-guides/incremental-static-regeneration-cache-components.md` |

[doc] "After enabling the flag, route segments that still export `dynamic`, `revalidate`, or `fetchCache` will error."
[doc] Cache Components requires the Node.js runtime. `use cache` is **not supported with `output: 'export'`**.

## 1. App Router file conventions (16.x)

```
src/app/
  layout.tsx          # root layout REQUIRED, must render <html><body>
  page.tsx            # makes segment public
  loading.tsx         # <Suspense> around page + nested layouts (NOT same-segment layout)
  error.tsx           # 'use client' required; props { error, retry } (retry stable in 16.3)
  global-error.tsx    # 'use client'; own <html><body>; no metadata export (use <title>)
  not-found.tsx       # rendered on notFound(); root one also catches unmatched URLs
  template.tsx, default.tsx (parallel slots)
  (group)/            # route group, not in URL; multiple root layouts => full page load between them
  [slug]/ [...slug]/ [[...slug]]/
  route.ts            # cannot coexist with page.tsx in same segment
  robots.ts sitemap.ts manifest.ts icon.tsx apple-icon.tsx favicon.ico opengraph-image.tsx twitter-image.tsx
proxy.ts              # at src/proxy.ts (same level as app/) — was middleware.ts
```
Hierarchy [doc]: `layout > template > error > loading > not-found > page`.

### params / searchParams are Promises (sync access REMOVED in 16)
[doc] "Starting with **Next.js 16**, synchronous access is fully removed." Applies to `cookies`, `headers`, `draftMode`, `params` in layout/page/route/default/opengraph-image/twitter-image/icon/apple-icon, `searchParams` in page.
```tsx
// Global helpers, no import; generated by `next dev` / `next build` / `next typegen`
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  const query = await props.searchParams
}
export default function Layout(props: LayoutProps<'/dashboard'>) { return props.children }
export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params
}
```
Note: some reference pages (cookies/headers/page) still say "you can still access it synchronously in Next.js 15" — ignore, the v16 upgrade guide is authoritative.

### generateStaticParams
```tsx
export async function generateStaticParams() {
  return posts.map((p) => ({ slug: p.slug }))      // [{ slug: string }]; catch-all => { slug: string[] }
}
// child segment receives parent params SYNCHRONOUSLY:
export async function generateStaticParams({ params: { category } }: { params: { category: string } }) {}
```
- [doc] Runs before layouts/pages at build; NOT called again during ISR revalidation; called on navigation in `next dev`.
- [doc] `fetch` is memoized across `generate*` functions, layouts, pages.
- Previous model: return `[]` (or `dynamic = 'force-static'`) to render all paths on first visit; `export const dynamicParams = false` => unlisted = 404.
- Cache Components: must return >= 1 param; `dynamicParams` not allowed — call `notFound()` for unknown slugs instead. Removing `generateStaticParams` "opts the route out of ISR, so Next.js renders it on every request, even when it uses `use cache`".

### Route segment config (what still exists)
[doc] Table in 16.3: `dynamicParams` (bool, default true), `runtime` (`'nodejs'` | `'edge'` **deprecated**), `preferredRegion` (deprecated), `maxDuration`. Plus `instant` and `prefetch` (Cache Components only). `dynamic`, `revalidate`, `fetchCache` live only in the "previous model" guide. `experimental_ppr` removed.
- [doc] `revalidate` must be statically analyzable: `600` OK, `60 * 10` NOT.

## 2. Caching & rendering

### Build output symbols [doc `02-guides/building.md`]
`○` Static | `◐` Partial Prerender (CC only) | `●` SSG (generateStaticParams) | `ƒ` Dynamic. Build table also shows `Revalidate` / `Expire` columns. `size`/`First Load JS` columns removed in 16.

### What makes a route dynamic
- Previous model: Request-time APIs (`cookies()`, `headers()`, `searchParams`, `draftMode`, `connection()`), `fetch(..., {cache:'no-store'})` / `revalidate: 0`, `export const dynamic = 'force-dynamic'`, `revalidate = 0`. [doc] `fetch` is **not cached by default**, but a fetch reachable *before* any Request-time API runs once at build (route prerendered up to that point).
- Cache Components: uncached async IO (fetch/DB/async fs) or runtime APIs not wrapped in `<Suspense>` => "blocking-route" dev insight / build error. Sync IO that's deterministic (`fs.readFileSync`, imports, `node:sqlite`, pure computation) prerenders automatically. [doc] "read them once at module scope instead of during rendering" for config/fonts.
- `useSearchParams()` in a client component on a static page **must** be inside `<Suspense>` or the production build fails (`missing-suspense-with-csr-bailout`) [doc].

### Previous model: static page that changes daily
```tsx
// src/app/page.tsx
export const revalidate = 86400 // literal only; lowest revalidate across layouts/pages/fetches wins
export default async function Page() {
  const data = await fetch(URL, { next: { revalidate: 86400, tags: ['daily'] } })
  // ...
}
```
- ISR is stale-while-revalidate: first request after the window gets the **stale** page and triggers background regen [doc]. Not aligned to midnight.
- Debug header `x-nextjs-cache: HIT|STALE|MISS|REVALIDATED` [doc].
- Non-fetch data: `unstable_cache(fn, ['key'], { tags, revalidate })` (still `unstable_`, but [doc] recommended for data that must persist across deploys).

### Cache Components model
```tsx
import { cacheLife, cacheTag } from 'next/cache'
export default async function Page() {
  'use cache'                 // must be first statement; function must be async
  cacheLife('days')           // ALWAYS set one; implicit 'default' otherwise
  cacheTag('daily')
  const items = await getItems()
  return <List items={items} />
}
```
- Directive levels: file top (all exports cached), function, component, `page`/`layout` file (each segment cached independently; cached layout does not cache `children`) [doc].
- [doc] `cacheLife` cannot be called at module scope; only inside a cache scope; one call per invocation.
- Profiles [doc]:

| profile | stale | revalidate | expire |
|---|---|---|---|
| default | 5m | 15m | never |
| seconds | 30s | 1s | 1m |
| minutes | 5m | 1m | 1h |
| hours | 5m | 1h | 1d |
| days | 5m | 1d | 1w |
| weeks | 5m | 1w | 30d |
| max | 5m | 30d | 1y |

- Inline: `cacheLife({ stale: 3600, revalidate: 86400, expire: 172800 })`; omitted fields inherit `default`; `expire` must be > `revalidate`.
- [doc] **Prerender exclusion**: `revalidate: 0` or `expire < 5 min` => dynamic hole (not in prerender); `stale < 30s` => excluded; `stale` 30s..5m => in prerender but not App Shell. Of presets only `seconds` is excluded.
- [doc] Nested `use cache` without explicit outer `cacheLife`: inner shorter lifetime shrinks outer; a short-lived inner (e.g. `seconds`) **throws during prerender**.
- [doc] Cache key = build ID + function ID + serialized args + captured closure vars. **New deploy = empty cache** (even `use cache: remote`).
- [doc] Args/returns must be serializable (no class instances, functions except pass-through; JSX OK as return). `URL` not serializable — return `metadataBase` as string from cached `generateMetadata`.
- [doc] Cannot call `cookies()`/`headers()`/`searchParams` inside a cache scope (also transitively); read outside and pass values as args. Passing a runtime **Promise** into a cached fn hangs the build ~50s ("Filling a cache during prerender timed out").
- [doc] Runtime storage: default in-memory LRU; on serverless (Vercel) entries **typically don't persist across requests**; build-time prerender caching works normally. `'use cache: remote'` = durable shared handler (network hop, platform fees). `'use cache: private'` = per-user, browser-only.
- [doc] `React.cache` values are NOT visible inside `use cache` scopes.
- Draft Mode: cached fns re-execute every request; `draftMode().isEnabled` readable inside cache.
- Debug: `NEXT_PRIVATE_DEBUG_CACHE=1 next start`.

### Date / random / connection / io (Cache Components)
```tsx
import { io } from 'next/cache'          // 16.3; preferred
import { connection } from 'next/server' // waits for a real request; blocks prefetch
async function Now() { await io(); return <p>{new Date().toISOString()}</p> } // wrap in <Suspense>
// Client component: use(io()) before Date.now()
```
- [doc] Alternative: put `new Date()` inside `'use cache'` => value captured into the static shell until revalidate.
- [doc] `io()` "resolves immediately" outside Cache Components, during requests, inside cache scopes, in `generateStaticParams`, and in the browser.
- [doc] `instant = false` does NOT clear sync-IO build errors (`new Date()`, `Math.random()`, `crypto.randomUUID()`).
- [doc] `performance.now()` is not guarded.
- Locale/timezone formatting: server formats in server TZ/locale; client `toLocaleDateString()` => hydration mismatch. Docs recommend inline `<script>` rewrite before paint (`02-guides/preventing-flash-before-hydration.md`); test with `TZ=UTC LANG=ja_JP.UTF-8 next dev`.

### Recipe: "static but changes daily"
1. Previous model: `export const revalidate = 86400` (+ `generateStaticParams` for dynamic routes).
2. Cache Components: page/data fn `'use cache'` + `cacheLife('days')` or custom profile in `next.config.ts` `cacheLife: { daily: {...} }`.
3. Exact rollover time (e.g. midnight MSK) [inf]: neither time-based option aligns to wall-clock. Add a Route Handler hit by a scheduler (Vercel Cron is a Vercel feature, not in Next docs) that calls `revalidateTag('daily', { expire: 0 })` (next request blocks for fresh data) or `revalidatePath('/')`. `updateTag` is Server-Actions-only.
4. Compute "day of" from a date captured at regeneration, not from request time, to keep the page static.

### On-demand revalidation [doc]
```ts
revalidateTag(tag: string, profile: string | { expire?: number }): void  // Server Fns + Route Handlers
updateTag(tag)        // Server Actions only; read-your-writes (immediate expire)
revalidatePath(path: string, type?: 'page' | 'layout') // type REQUIRED for patterns: ('/blog/[slug]','page'); omit for literal '/blog/post-1'
refresh()             // Server Actions: refetch current route RSC, no cache invalidation
```
- `'max'` = serve stale while revalidating (recommended); `{ expire: 0 }` = next request blocks.
- [doc] "A revalidation is triggered by a request, not by the `revalidateTag` call."
- Tag max 256 chars. Proxy is NOT executed for on-demand ISR requests — revalidate exact paths.

### Bots (SEO) [doc]
- With Cache Components, HTML-limited bots (regex in installed `html-bots.js`: Google-* crawlers, Bingbot, `yandex`, `vkShare`, `facebookexternalhit`, `Twitterbot`, `LinkedInBot`, `Slackbot`, `Discordbot`, `WhatsApp`, ...) **skip the static shell and render dynamically**. If the shell depends on build-time-only data (files not traced into the function), crawlers can fail while users succeed. Make that data available at runtime (`outputFileTracingIncludes`).
- Streaming metadata: if `generateMetadata` is dynamic, tags are appended to `<body>` for normal UAs; HTML-limited bots get them in `<head>`. Fully prerendered pages include metadata in initial `<head>`. `TelegramBot` is **not** in the default list [inf: matters only if metadata streams].

## 3. Metadata API

```tsx
import type { Metadata, ResolvingMetadata, Viewport } from 'next'

// src/app/layout.tsx
export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),        // relative URL fields without it = BUILD ERROR
  title: { template: '%s | Site', default: 'Site' },   // default REQUIRED with template
  description: '...',
  alternates: { canonical: '/', languages: { 'ru-RU': '/ru' }, types: { 'application/rss+xml': '/rss.xml' } },
  openGraph: { type: 'website', siteName: 'Site', locale: 'ru_RU', images: '/og.png' },
  twitter: { card: 'summary_large_image', creator: '@x', images: ['/og.png'] },
  robots: { index: true, follow: true, googleBot: { 'max-image-preview': 'large', 'max-snippet': -1 } },
  appleWebApp: { title: 'Site', statusBarStyle: 'black-translucent' },
  // icons: prefer file conventions
}
export const viewport: Viewport = { themeColor: '#000' }   // themeColor NOT in metadata

// page.tsx
export async function generateMetadata(
  { params, searchParams }: PageProps<'/blog/[slug]'>, parent: ResolvingMetadata
): Promise<Metadata> {
  const { slug } = await params
  const prev = (await parent).openGraph?.images || []
  return { title: post.title, alternates: { canonical: `/blog/${slug}` }, openGraph: { images: [...prev] } }
}
```
- [doc] Server Components only; cannot export both `metadata` and `generateMetadata` from one segment; `searchParams` only in pages; `notFound()`/`redirect()` allowed.
- [doc] **Shallow merge** by segment order: a child that sets `openGraph` replaces ALL parent `openGraph` fields (spread a shared object to keep images). Child without `openGraph` inherits parent's.
- [doc] File-based metadata (opengraph-image, icon...) overrides `metadata`/`generateMetadata`.
- [doc] metadataBase composition: `'/payments'`, `'./payments'`, `'../payments'` all => `https://acme.com/payments`.
- [doc] Dedupe page/metadata fetches with `React.cache`; `fetch` auto-memoized.
- Cache Components: a `generateMetadata` that does uncached IO on an otherwise fully prerenderable page => error; fix with `'use cache'` inside `generateMetadata`.
- Defaults always emitted: `<meta charset>` and `<meta name="viewport" content="width=device-width, initial-scale=1">`.

### robots.ts / sitemap.ts / manifest.ts (root of `src/app/`; special Route Handlers, cached/static by default)
```ts
import type { MetadataRoute } from 'next'
export default function robots(): MetadataRoute.Robots {
  return { rules: { userAgent: '*', allow: '/', disallow: '/private/' }, sitemap: 'https://example.com/sitemap.xml' }
} // rules[].other (16.3) passes non-standard directives verbatim; also crawlDelay, host

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  return [{ url: 'https://example.com', lastModified: new Date(), changeFrequency: 'daily', priority: 1,
            alternates: { languages: { en: 'https://example.com/en' } }, images: ['https://.../a.jpg'] }]
}
// Split: export async function generateSitemaps() { return [{ id: 0 }, { id: 1 }] }
//        export default async function sitemap(props: { id: Promise<string> }) { const id = await props.id } // id is Promise<string> in 16
// Google limit 50,000 URLs per sitemap. Nested app/products/sitemap.ts also works.

export default function manifest(): MetadataRoute.Manifest {
  return { name, short_name, description, start_url: '/', display: 'standalone',
           background_color: '#fff', theme_color: '#fff', icons: [{ src: '/icon-192.png', sizes: '192x192', type: 'image/png' }] }
}
```
- [inf] `new Date()` in `sitemap.ts` under Cache Components may trigger the sync-IO rule — use content dates or `'use cache'`.
- PWA guide (`02-guides/progressive-web-apps.md`): manifest + hand-written `public/sw.js` service worker; no built-in SW plugin. Experimental `useOffline` config/hook exists.

## 4. OG images (`opengraph-image.tsx`, `ImageResponse`)

```tsx
// src/app/blog/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'          // NOT next/server (moved in v14)
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'

export const alt = 'Post'
export const size = { width: 1200, height: 630 }
export const contentType = 'image/png'

// [doc] read static assets ONCE at module scope (path relative to project root = web/)
const fontRegular = await readFile(join(process.cwd(), 'assets/fonts/Font-Regular.ttf'))
const fontBold    = await readFile(join(process.cwd(), 'assets/fonts/Font-Bold.ttf'))

export default async function Image({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params                  // Promise in 16 (also `id` from generateImageMetadata)
  const post = await getPost(slug)
  return new ImageResponse(
    <div style={{ display: 'flex', width: '100%', height: '100%', fontFamily: 'Font', fontSize: 64 }}>{post.title}</div>,
    { ...size, fonts: [
      { name: 'Font', data: fontRegular, weight: 400, style: 'normal' },
      { name: 'Font', data: fontBold,    weight: 700, style: 'normal' },
    ] },
  )
}
```
`ImageResponse(element, { width=1200, height=630, emoji?: 'twemoji'|'blobmoji'|'noto'|'openmoji', fonts?: {name, data: ArrayBuffer, weight: number, style: 'normal'|'italic'}[], debug, status, statusText, headers })` [doc].
- [doc] Satori + Resvg -> PNG. **Flexbox + subset of CSS only; no `display: grid`.** Every multi-child div needs `display: 'flex'` [inf from Satori].
- [doc] Fonts: **only `ttf`, `otf`, `woff`** (no woff2); ttf/otf parse fastest. `next/font` cannot be used here [inf].
- [doc] **Max bundle 500KB** (JSX, CSS, fonts, images). [inf] For Cyrillic, ship a TTF subset with Cyrillic+Latin glyphs (Cyrillic not mentioned in docs; Satori renders whatever glyphs the font has, missing glyphs fall back/tofu). Reading via `readFile` keeps fonts out of the JS bundle, but subset anyway.
- Local images: `readFile(..., 'base64')` -> `data:image/png;base64,...` in `<img src>`; ArrayBuffer src needs `@ts-expect-error`.
- [doc] Static files: `opengraph-image.(jpg|jpeg|png|gif)` + `opengraph-image.alt.txt`; OG file <= **8MB**, twitter-image <= **5MB** (build fails otherwise).
- [doc] Generated images are statically optimized (build time) unless they use Request-time APIs or uncached data. More specific segment's image wins.
- Runtime: Node.js (default). Edge runtime is **deprecated**; don't add `export const runtime = 'edge'`.
- `generateImageMetadata({ params })` gets SYNC params; returns `[{ id, alt, size, contentType }]`.
- [inf] Check `next build` that `/blog/[slug]/opengraph-image` is `●`/`○` for gSP slugs; dynamic metadata images show `ƒ`. If it's dynamic on Vercel, ensure font files are traced (`outputFileTracingIncludes`).

## 5. Fonts (`next/font/google`)

```tsx
// src/app/fonts.ts
import { Inter, Roboto_Mono } from 'next/font/google'
export const inter = Inter({

// layout.tsx
<html lang="ru" className={`${inter.variable} ${mono.variable}`}>

@import 'tailwindcss';

- [doc] Use `inter.className` / `inter.style` / `inter.variable`. Local: `next/font/local` with `src`, `declarations`.

<Image src={hero} alt="" placeholder="blur" preload sizes="100vw" />
<Image src="https://cdn.example.com/a.jpg" alt="" fill sizes="(max-width: 768px) 100vw, 33vw"
       placeholder="blur" blurDataURL="data:image/..." />   // remote: blurDataURL manual
```
- Props [doc]: `src alt width height fill loader sizes quality preload placeholder('empty'|'blur'|'data:...') style onLoad onError loading('lazy' default|'eager') blurDataURL unoptimized overrideSrc decoding`. `priority` deprecated; `onLoadingComplete` deprecated.
- [doc] `preload` = `<link>` in head; "In most cases, you should use `loading="eager"` or `fetchPriority="high"` instead of `preload`." Don't combine with `loading`/`fetchPriority`.
- [doc] Without `sizes`: limited 1x/2x srcset; with `sizes`: full width-based srcset. Needed with `fill` or CSS-responsive images.
- Config defaults (16): `deviceSizes [640,750,828,1080,1200,1920,2048,3840]`, `imageSizes [32,48,64,96,128,256,384]`, `qualities [75]` (required/allowlist; REST requests with other q => 400), `formats ['image/webp']`, `minimumCacheTTL 14400`, `maximumRedirects 3`, local IPs blocked (`dangerouslyAllowLocalIP`).
- [doc] AVIF ~20% smaller, ~50% slower encode; each format cached separately.
- [doc] `remotePatterns`: `[new URL('https://example.com/account123/**')]` or `{ protocol, hostname: '**.example.com', port, pathname, search }`; omitted fields imply `**`.
- [doc] Local `src` with query string (`/a.png?v=1`) requires `images.localPatterns[].search`.
- [doc] No cache invalidation for optimized images; prefer static imports (immutable hashed).
- `output: 'export'` => default loader unsupported; needs custom `loaderFile`.

## 7. Route Handlers & Server Actions

```ts
// src/app/api/items/[id]/route.ts
import type { NextRequest } from 'next/server'
export async function GET(request: NextRequest, ctx: RouteContext<'/api/items/[id]'>) {
  const { id } = await ctx.params                 // Promise
  const q = request.nextUrl.searchParams.get('q')
  return Response.json({ id, q })
}
// also HEAD POST PUT PATCH DELETE OPTIONS (OPTIONS auto-implemented if omitted); others => 405
```
- [doc] **Not cached by default.** Previous model: cache a GET with `export const dynamic = 'force-static'` (other methods never cached). Can use `generateStaticParams` in route.ts for static API JSON.
- Cache Components: GET handlers prerender if they don't touch uncached/runtime data (`req.url`, `request.headers`, body, `cookies()`, `Math.random()` stop prerender). [doc] "`use cache` cannot be used directly inside a Route Handler body; extract it to a helper function."
- Special handlers (`sitemap`, `robots`, `manifest`, `opengraph-image`, `icon`) static by default.
- `runtime = 'edge'` deprecated; `maxDuration` export for platform limits.

Server Actions:
```ts
'use server'                                  // file-level => every export is a Server Function
import { revalidateTag, updateTag, refresh } from 'next/cache'
export async function subscribe(formData: FormData) {
  // validate input + authz here; actions are public endpoints [doc]
  updateTag('subs')
}
// <form action={subscribe}>…</form>   — receives FormData
// client: const [state, action, pending] = useActionState(fn, init); startTransition(action)
```
- [doc] Config: `experimental.serverActions: { allowedOrigins, bodySizeLimit: '2mb' }`. Set `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` stable across instances. Action IDs rotate on deploy ("Failed to find Server Action").
- [doc] `updateTag`/`revalidatePath`/`refresh` in an action re-render the current route in the same response; `revalidateTag(..., 'max')` does not.
- Not available with `output: 'export'`.

## 8. Client components & View Transitions

- `'use client'` at top of file, before imports; marks a client **entry point** (only needed on files imported from Server Components). Props must be serializable (no functions, except Server Actions) [doc].
- ESLint rule `@next/next/no-async-client-component`: client components can't be async.
- Cache Components: routes kept in `<Activity mode="hidden">` — `useState`, form inputs, `useActionState` results, open dropdowns **persist** when navigating back. Reset explicitly (`useLayoutEffect` cleanup, URL-derived state) [doc `02-guides/preserving-ui-state.md`].
- Scroll: Next 16 no longer overrides `scroll-behavior: smooth` during navigation; add `<html data-scroll-behavior="smooth">` to restore old override [doc].

### View Transitions (documented, stable usage, no config) [doc `02-guides/view-transitions.md`]
```tsx
import { ViewTransition } from 'react'   // NOT unstable_ViewTransition; typed in @types/react 19.3 (verified)
// Shared element morph: same `name` on both pages
<ViewTransition name={`cover-${id}`} share="morph" default="none"><Image … /></ViewTransition>
// Suspense reveal
<Suspense fallback={<ViewTransition exit="slide-down" default="none"><Skeleton/></ViewTransition>}>
  <ViewTransition enter="slide-up" default="none"><Content/></ViewTransition>
</Suspense>
// Directional nav: tag links, map types per page (put wrapper in page.tsx, NOT layout)
<Link href="/x" transitionTypes={['nav-forward']}>…</Link>      // Link prop added 16.2; router.push(url, { transitionTypes }) too
<ViewTransition enter={{ 'nav-forward': 'nav-forward', 'nav-back': 'nav-back', default: 'none' }}
                exit={{ 'nav-forward': 'nav-forward', 'nav-back': 'nav-back', default: 'none' }} default="none">…</ViewTransition>
// Same-route crossfade
<ViewTransition key={slug} name="collection" share="auto" enter="auto" default="none">…</ViewTransition>
```
CSS hooks: `::view-transition-group(.morph)`, `::view-transition-old(.slide-down)`, `::view-transition-new(.nav-forward)`; persistent header via `style={{ viewTransitionName: 'site-header' }}` + `::view-transition-group(site-header){animation:none;z-index:100}` + `::view-transition-old(site-header){display:none}`.
- [doc] Triggered by Transitions, `<Suspense>`, `useDeferredValue` — **not** plain `setState`. Route navigations are transitions => auto-activate.
- [doc] `default="none"` stops every named VT from animating on unrelated transitions; with `default="none"` you MUST keep `share`, or the morph silently stops.
- [doc] Morph only pairs when destination renders in the same commit (prefetched/cached); if it suspends into a fallback first, no pair forms.
- [doc] Browser back/forward carry no transition type -> no directional slide (morph still works).
- [doc] Add `::view-transition { pointer-events: none; }` and a `prefers-reduced-motion` block zeroing `animation-duration`.
- [doc] Needs Chromium 125+/recent Safari/Firefox for types + `view-transition-class`; unsupported browsers just don't animate.

## 10. Surprises that break Next 14/15 code

1. Sync `params`/`searchParams`/`cookies()`/`headers()`/`draftMode()` **removed** — always `await`. Also `opengraph-image`/`icon` `params` + `id`, and `sitemap` `id` (now `Promise<string>`).
2. `middleware.ts` → `proxy.ts` (`export function proxy`), Node runtime only. Edge runtime deprecated everywhere; ISR/Cache Components don't run on edge.
3. `revalidateTag('x')` single-arg = TS error; use `revalidateTag('x', 'max')` or `{ expire: 0 }`; `updateTag` for read-your-writes in actions.
4. Enabling `cacheComponents` is not a rename: `dynamic`/`revalidate`/`fetchCache`/`dynamicParams` exports error; `generateStaticParams` must return >= 1; `new Date()`/`Math.random()` in render fail the build; uncached data outside `<Suspense>` fails validation.
5. Turbopack default: webpack configs break `next build`. `next lint` gone; `next build` doesn't lint.
6. `next/image`: `qualities` default `[75]` (other qualities coerced), `imageSizes` lost 16, `minimumCacheTTL` 4h, local images with `?query` need `localPatterns.search`, max 3 redirects, `priority` → `preload`, `images.domains` deprecated.
7. Parallel route slots **require** `default.tsx` or build fails.
8. `scroll-behavior: smooth` no longer overridden on navigation (opt back in with `data-scroll-behavior="smooth"`).
9. `error.tsx` should use `retry()` (refetch) — `reset()` only clears state.
10. Build output no longer shows `size` / `First Load JS`; new `Revalidate`/`Expire` columns and `◐` symbol.
11. Cache Components: Activity keeps previous routes mounted (state persists); bots (Google, Yandex, VK, FB...) re-render dynamically — build-only data can break crawls.
12. `ImageResponse` must come from `next/og`; fonts ttf/otf/woff only; 500KB bundle cap; no CSS grid.
13. `serverRuntimeConfig`/`publicRuntimeConfig`, AMP, `devIndicators.buildActivity` removed. Use `connection()` before reading `process.env` if it must be read at runtime instead of baked at build.
14. React 19.2 canary features available in App Router: `<ViewTransition>`, `useEffectEvent`, `<Activity>`.
