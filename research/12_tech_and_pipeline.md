# 12 — Пайплайн разработки и технический стек (октябрь 2026)

Дата: 2026-10-06. Версии пакетов проверены через `npm view` в этот день. Лимиты Vercel взяты из документации (выгружена в markdown, `last_updated` сентябрь–август 2026). Через Vercel MCP я только читал. Ничего не создавал и не менял.

Связанные файлы: `00_context.md`, `01_critique.md`, `13_synthetic_research.md`, `08_brand_audit.md`, `next16_cheatsheet.md` (там подробности по Next 16, здесь их не повторяю), код в `web/`.

## Коротко

1. **Стек менять не нужно.** Уже стоят Next 16.3.8 (это и есть последняя версия), React 19.2.8, Tailwind 4.3.3, TypeScript 5.9.3, Motion 14.0.0, `@vercel/analytics` 2.0.1. Ничего не обновлять до запуска: TypeScript 7, ESLint 10 и React 19.3 вышли недавно, а выигрыша для MVP не дают.
2. **«Ежедневное открытие» по МСК без cron:** главная — ISR с `revalidate = 300`, страница рассказа — SSG + `dynamicParams` + `revalidate = 3600` + `notFound()` для будущих выпусков. Cron на Hobby срабатывает раз в сутки с точностью ±59 минут, поэтому он только вспомогательный (сбросить кеш, пингануть IndexNow).
3. **Счётчики реакций:** правильный вариант — Upstash Redis. **Через Vercel MCP его не поднять:** инструмента для создания ресурсов Marketplace нет. Интеграция Upstash в команде уже установлена (с 4 октября), но ни к одному проекту не подключена, а бесплатного тарифа в ответе API нет. Нужны 2 минуты владельца в дашборде. До этого реакции работают локально, код готов к подключению по переменным окружения.
4. **Vercel Blob для счётчиков не годится**, хотя его можно создать через MCP и он уже стоит в `package.json`. На Hobby включено 2000 «продвинутых» операций в месяц, каждая запись — одна операция. При превышении Blob блокируется на 30 дней. Global Config (бывший Edge Config): 100 записей в месяц, через MCP не создаётся.
5. **Анимации:** книга — на CSS 3D без WebGL. Оркестровка жестов и пружин — Motion через `LazyMotion` + `m`, это ~4,6 КБ стартового кода. Переход «книга → читалка» — React `<ViewTransition>`. GSAP не нужен: он дублирует Motion и крутится в главном потоке. Three.js не нужен: 181 КБ gzip только ядро.
6. **Главная скрытая угроза бюджета — оптимизация картинок.** На Hobby 5000 трансформаций в месяц, и они считаются на каждый MISS и STALE. При кеше 4 часа по умолчанию обложки съедят лимит, после этого новые картинки отдают 402, и вместо обложки дня будет alt-текст. Решение: заранее нарезать обложки скриптом и отдавать их как статику (`unoptimized`).
7. **Второй лимит — 1 млн CDN-запросов в месяц.** Считается каждый файл: HTML, чанки, шрифты, картинки. Это примерно 40–100 тыс. просмотров в месяц. Если пост в ВК «выстрелит», сайт на Hobby встанет до конца 30-дневного окна. Надо держать мало файлов на страницу и иметь план перехода на Pro.
8. **Аналитика:** Vercel Web Analytics на Hobby считает только просмотры. Пользовательских событий там нет, UTM тоже. Дочитываемость, реакции и шеринг на Hobby ею не измерить. Нужны свои агрегированные счётчики в том же Redis (или Яндекс Метрика — но это cookies, и нужен баннер согласия).
9. **Vercel MCP:** вызовы с `teamId` падают с 403 (токен не авторизован на scope `anime-4dac`). Без `teamId` работает в команде по умолчанию. `create_git_project` требует `teamId` и, скорее всего, упадёт. Обходной путь — `create_project` с `gitRepository` без `teamId`, либо владелец переавторизует MCP.
10. **Не согласен с прошлой критикой** в одном пункте. «Держать проект статически экспортируемым» не нужно. Достаточно, чтобы он запускался на любом Node-хосте (`next start`). Тогда ISR и API сохраняются, а план Б (российский VPS) — те же 1–2 часа.

## 0. Критика вводных с технической стороны

| Идея (откуда) | Вердикт | Почему |
|---|---|---|
| 3D-книга, «раскрытие как блюдо» (владелец) | **Изменить**: CSS 3D + одна метафора | WebGL ради одного объекта — это 180+ КБ JS, нагрев и рывки на дешёвых Android. CSS 3D даёт тот же объём (см. B6). Метафор две: «блюдо под клошем» и «распечатать». Бренд-аудит выбрал «сургучную печать», технически обе дешёвые, но делать надо одну |
| «Web3-дизайн», необычное меню (владелец) | **Осторожно** | Нестандартная навигация бьёт по находимости и доступности. Одно необычное решение на экран, обычные `<button>`/`<a>` внутри, фокус с клавиатуры, VoiceOver |
| Жидкое стекло (владелец) | **Выкинуть** | `backdrop-filter` поверх прокручиваемого текста перерисовывается каждый кадр. На слабых Android это рывки. Критика уже предложила кальку: делать её статичной полупрозрачной заливкой с готовой текстурой, без живого blur |
| Грейн (владелец) | **Оставить, но запечь** | Живой шум (`feTurbulence`, анимированный canvas) на весь экран дорогой. Нужна маленькая тайловая текстура или грейн прямо в обложках. `mix-blend-mode` на родителе книги «сплющивает» 3D |
| Профиль (владелец) | **Не нужен** | Всё в localStorage. Перенос полки — «ключ полки» (код/ссылка), без сервера |
| Стрик (владелец) | **Не нужен** | Синтетика против (1,2 из 5). Технически стрик в localStorage сгорает от ITP Safari через 7 дней без визита |
| Telegram Mini App (прошлый диалог) | **Выкинуть** | Telegram в РФ заблокирован (см. `01_critique.md` §0.1) |
| PWA + утренний пуш (прошлый диалог) | **Позже** | Для пуша нужны хранилище подписок, VAPID-ключи и ежедневная отправка. На iOS пуш работает только после установки на экран «Домой». В MVP — манифест и иконки |
| «Статически экспортируемый проект» (`01_critique.md` §0.2) | **Изменить** | `output: 'export'` убивает ISR, API реакций, OG по запросу и оптимизацию картинок. Переносимость даёт и обычный `next start` на VPS. Критерий: никаких Vercel-специфичных API в коде, кроме аналитики (на другом хосте она просто молчит) |
| Ячейки `/den/2026-10-06` (`01_critique.md` §1) | **Не делать в MVP** | Страница дня — дубль страницы рассказа: нужен canonical, она слабая для SEO и лишняя для кода. Номер выпуска и дата живут на странице рассказа и в архиве. Слепой режим уже сделан через `?z=1` и sessionStorage |
| «День меняется по местному времени — Must, дёшево» (`13_synthetic_research.md`) | **Не дёшево. В MVP — МСК** | Чтобы во Владивостоке (МСК+7) открыть «завтрашний» по Москве рассказ, сервер должен отдавать его на 7 часов раньше. Это ломает простую проверку «выпуск ≤ сегодня по МСК». Вариант на потом — в разделе B3 |
| «Офлайн: сегодняшний и два следующих» (`13_synthetic_research.md`) | **Только сегодняшний и прочитанные** | Закешировать будущие — значит отдать их клиенту, и магия «завтра закрыто» пропадает |
| Email-рассылка «рассказ утром» (`01_critique.md`, `02_competitors_direct.md`) | **Не в эту ночь** | Почта — персональные данные. По 242-ФЗ их первичная запись должна быть в базе на территории РФ. Upstash и Vercel не подходят. Штрафы за нелокализацию для юрлиц — 2–6 млн ₽ ([pravo.ru](https://pravo.ru/news/212293/), [Т—Бизнес](https://secrets.tbank.ru/blogi-kompanij/personalnye-dannye-2026/)). Нужен российский сервис рассылок с их формой, плюс политика и согласие |
| `@vercel/blob` в `web/package.json` (текущая сборка) | **Не использовать для реакций** | См. B5 |

## A2. Как ужать пайплайн для FantPub

Пайплайн — это меню, а не обязательный ритуал. Для MVP за одну ночь силами агентов:

- **Пропустить:** формальный RICE (нет данных об охвате), CJM сверх двух сценариев, Figma-вайрфреймы (код-прототип на реальных текстах быстрее и честнее), дизайн-систему как Figma-библиотеку (токенов в CSS достаточно).
- **Не пропускать ни в коем случае:**
  1. **Реестр прав**: автор, годы жизни, переводчик, годы жизни переводчика, источник, статус PD. Это единственный артефакт, ошибка в котором стоит денег. На FantPub 1.0 уже была перепечатка Кларка.
  2. **Запас контента** на 30 дней вперёд (`01_critique.md` §1).
  3. **Тесты смены дня**: полночь МСК, кеш, будущий slug.
  4. **Проверка с мобильного интернета РФ**: четыре оператора, `*.vercel.app` и свой домен.
  5. **События аналитики**, определённые до запуска.
  6. **Критерии отказа**: например, «если D7 < 10% через 6 недель — меняем формат».
- **Код — это прототип.** Владелец-дизайнер утром смотрит превью-деплой, а не картинки. Правки — в токенах и компонентах.
- **Реальные люди — сразу после запуска**: опрос в паблике ВК, 5 созвонов, Вебвизор (если поставим Метрику) на первых 100 сессиях. Список проверок уже есть в `13_synthetic_research.md` §12.

## B2. Архитектура на Vercel Hobby

```
Браузер ── CDN Vercel (статика, ISR-кеш) ── Функции (fra1)
  │                                          ├─ ISR-регенерация /, /arhiv, /rasskaz/*
  │ localStorage: полка, прогресс,           ├─ /api/react  (реакции)  ──► Upstash Redis
  │ настройки, реакции, deviceId             ├─ /api/event  (агрегаты) ──► Upstash Redis
  │                                          └─ /api/cron/daily (раз в сутки ±59 мин)
  └─ Service Worker (позже): оболочка + прочитанные
Контент: web/content/stories/*.md + authors.json (в git, читается только на сервере)
```

Принципы:
1. **Контент — файлы в git.** CMS не нужна. Владелец и агенты правят Markdown, мерж в `main` → деплой. Будущие рассказы лежат в бандле функций (`server-only`), но не в клиентском JS и не в sitemap.
2. **Все страницы — статика или ISR.** Динамика — только `/api/*`, и её отсутствие ничего не ломает: без Redis реакции просто локальные.
3. **Регион функций — `fra1`** (Франкфурт) вместо `iad1` по умолчанию. Это ближе к РФ: быстрее ISR-регенерация и API. Задаётся в настройках проекта или `vercel.json` → `"regions": ["fra1"]`.
4. **Ничего Vercel-специфичного в бизнес-логике.** Cron — обычный GET-роут с секретом: на VPS его дёрнет системный cron.

## B3. «Ежедневное открытие» по МСК

Текущий `web/src/lib/date.ts` корректен: МСК = UTC+3 без перехода на летнее время с 2014 года, номер выпуска считается от `LAUNCH_DATE`. `getStory()` уже возвращает `null` для будущих.

**Схема:**

```tsx
// src/app/rasskaz/[slug]/page.tsx
export const revalidate = 3600;     // только литерал
export const dynamicParams = true;  // новый выпуск дорендерится по первому запросу
export function generateStaticParams() {
  return getPublishedStories().map((s) => ({ slug: s.slug })); // опубликованные на момент сборки
}
export default async function Page({ params }: PageProps<'/rasskaz/[slug]'>) {
  const { slug } = await params;
  const story = getStory(slug);     // null, если выпуск ещё не открылся
  if (!story) notFound();
  // …
}
```

```tsx
// src/app/page.tsx — revalidate = 300, на сервере: getTodayStory()
// + клиентский страж: если вкладка пережила полночь или CDN отдал устаревшую копию
'use client';
export function DayGuard({ issue }: { issue: number }) {
  const router = useRouter();
  useEffect(() => {
    const check = () => { if (currentIssue() > issue) router.refresh(); };
    const t = setTimeout(check, 1500);       // первый запрос уже запустил регенерацию
    document.addEventListener('visibilitychange', check);
    return () => { clearTimeout(t); document.removeEventListener('visibilitychange', check); };
  }, [issue, router]);
  return null;
}
```

```json
// vercel.json
{
  "regions": ["fra1"],
  "crons": [{ "path": "/api/cron/daily", "schedule": "0 21 * * *" }]
}
```
`0 21 * * *` UTC — это 00:00 МСК. На Hobby задача сработает в окне 00:00–00:59 МСК. Роут проверяет `Authorization: Bearer ${CRON_SECRET}` и вызывает `revalidatePath('/')`, `revalidatePath('/arhiv')`, `revalidatePath('/rasskaz/[slug]', 'page')`, `revalidatePath('/sitemap.xml')`, а потом пингует IndexNow с адресом нового рассказа.

**Крайние случаи:**
- **ISR — это stale-while-revalidate.** Первый посетитель после полуночи получит старую главную и запустит регенерацию. Клиентский страж через 1,5 с сделает `refresh()`. Если и после этого день не сменился, показать состояние «Новый выпуск печатается…» с Пабчиком (`sleeping.webp`), а не вчерашнюю книгу как сегодняшнюю.
- **Кеш 404.** Если кто-то угадает slug будущего рассказа, 404 может закешироваться на `revalidate` (до часа). Документация Next 16 этот случай явно не описывает. Ссылок на будущие нет, так что риск низкий. Cron после полуночи сбрасывает кеш маршрута. **Проверить на превью.**
- **Сборка и номер выпуска.** `generateStaticParams` берёт «сегодня» на момент сборки. Деплой в 23:59 — это нормально: новый рассказ дорендерится по запросу.
- **Тестирование времени.** Логику дат надо покрыть юнит-тестами с фиксированным `now` (функции уже принимают `now`). На превью — env-переменная `FAKE_NOW` (только для preview, не для production).
- **Местное время (потом).** «Ворота» на сервере ставятся по самому раннему часовому поясу аудитории. Например, Камчатка (UTC+12, МСК+9): выпуск открывается на сервере, когда там наступило его число. Клиент показывает «сегодня» по своему локальному числу. Цена: рассказ доступен по прямой ссылке на 9 часов раньше полуночи по Москве, а «62% читателей сегодня…» размывается по поясам. Для MVP не нужно.

## B4. Локальное хранение прогресса

**Выбор: localStorage, не IndexedDB.** Причина — загрузочный скрипт в `<head>` (`layout.tsx`) должен **синхронно** прочитать тему, шрифт и слепой режим до первой отрисовки, иначе будет вспышка. IndexedDB асинхронный. Объём данных — килобайты.

Рекомендуемая схема (ключ `fantpub:v1` уже используется):

```ts
type SaveV1 = {
  v: 1;
  device: string;                                 // crypto.randomUUID(), только для дедупликации реакций
  prefs: { theme: 'auto'|'paper'|'dusk'|'night'; font: 'literata'|'ptserif'|'onest'; size: 1|2|3|4|5; leading: 'normal'|'loose' };
  read: Record<string, { at: number; done: boolean; pct: number; para?: number }>; // закладка до абзаца
  reactions: Record<string, 'wow'|'scary'|'sad'|'meh'>;
  seals: Record<number, true>;                    // ритуал выпуска N уже показан
  firstVisit: number; installAskedAt?: number;
};
```

Правила:
- Каждое чтение и запись — в `try/catch`. В приватном режиме и при переполнении запись бросает исключение.
- Позицию чтения писать с троттлингом (раз в 2–3 с) и на `pagehide`/`visibilitychange`. Не на каждый `scroll`.
- Миграции по полю `v`.
- **ITP Safari:** хранилище стирается после 7 дней без визита, если сайт не установлен на экран «Домой» ([WebKit](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)). Поэтому: полка не «сгорает» (без стриков), после 3 прочитанных — предложение установить PWA, `navigator.storage.persist()` после установки.
- **Встроенный браузер ВК** хранит данные отдельно от Safari и Chrome. Пришедший из ВК увидит пустую полку в обычном браузере. В MVP это нормально. Позже — «ключ полки»: экспорт состояния в короткую ссылку `#k=<base64url>` без сервера.
- В Redis из этого уходит только `device` (случайный UUID без связи с человеком) и агрегаты. IP не храним.

- Ключи:

## B6. Анимации: что быстрее на мобильном вебе

Главный факт для перфа: на слабом Android главный поток занят гидрацией в те самые секунды, когда мы показываем ритуал. **Анимации, которые идут в compositor-потоке** (CSS-переходы и keyframes по `transform`/`opacity`, WAAPI, View Transitions), остаются плавными. **Анимации на `requestAnimationFrame` в главном потоке** (GSAP, JS-пружины Motion для не-transform свойств, Three.js) в это время дёргаются.

| Технология | Вес | Поток | Сильное | Слабое | Роль в FantPub |
|---|---|---|---|---|---|

### Можно ли сделать книгу на CSS 3D без WebGL? Да.

Скелет (толщина книги `--t`):

```css
.scene { perspective: 1100px; }
.book  { --t: 26px; position: relative; width: min(62vw, 260px); aspect-ratio: 2 / 3;
         transform-style: preserve-3d; transform: rotateY(-24deg) rotateX(4deg); }
.face  { position: absolute; inset: 0; backface-visibility: hidden; -webkit-backface-visibility: hidden; }
.front { transform: translateZ(calc(var(--t) / 2)); transform-origin: left center; transform-style: preserve-3d; }
.back  { transform: rotateY(180deg) translateZ(calc(var(--t) / 2)); }
.spine { inset: 0 auto 0 calc(var(--t) / -2); width: var(--t); transform: rotateY(-90deg); }
.edge  { inset: 2% calc(var(--t) / -2) 2% auto; width: var(--t); transform: rotateY(90deg);
         background: repeating-linear-gradient(90deg, #efe6d2 0 1px, #d9ceb5 1px 2px); } /* обрез страниц */
.book[data-open] .front { transform: translateZ(calc(var(--t) / 2)) rotateY(-155deg); } /* петля — левый край */
```

Поворот вокруг корешка, внутренняя сторона обложки (`.front > .inside { transform: rotateY(180deg) }`), первая страница с заголовком и тень снизу — всё это обычные слои. Для мобильного достаточно 6–8 граней.

**Подводные камни (проверено практикой, не теорией):**
- 3D «сплющивается», если на `.book` или его предке стоит `overflow` ≠ `visible`, `opacity < 1`, `filter`, `mix-blend-mode`, `clip-path`, `mask`, `backdrop-filter`, `contain: paint`, `isolation: isolate`. Грейн, кальку и тени держать **соседними** слоями, а не родителями.
- Тень — отдельный элемент с размытым `radial-gradient` под книгой. Анимировать только его `transform`/`opacity`, а не `box-shadow`.
- Анимировать только `transform` и `opacity`. `will-change: transform` включать на время анимации. Не анимировать `perspective`.
- Против z-fighting — сдвиги `translateZ` на 0,5–1 px.
- Обложка — обычный `<img>` с явными размерами: она же LCP-элемент, рендерится сервером ещё до JS.
- Обёртка `@supports (transform-style: preserve-3d)`. Без поддержки — плоская обложка.

**Ритуал «сломать печать» (или «поднять клош»)** — SVG из 3–5 осколков. По тапу осколки разлетаются на Motion-пружинах (`transform` + `opacity`), 6–10 крошек сургуча на CSS keyframes, книга поворачивается и раскрывается. Итого ≤ 1,2 с, пропуск тапом, ритуал один раз на выпуск (флаг `seals[N]`). На Android можно добавить `navigator.vibrate(10)` в момент слома (iOS не поддерживает). Звук — нет. Клош технически так же дёшев (крышка уходит вверх, пар — 3 SVG-штриха), но метафору надо выбрать одну.

**`prefers-reduced-motion`:** кроссфейд 200 мс вместо разворота, никакого покачивания в простое, никакого гироскопа (на iOS он вызывает системный запрос разрешения).

**Перф-бюджет** (ориентиры, проверить сборкой):
- LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на среднем Android в режиме Slow 4G ([web.dev](https://web.dev/articles/vitals)).
- JS первой загрузки: страница рассказа — ≈ база Next/React + ≤ 30 КБ своего. Главная — + Motion `domAnimation`. Замерить `next experimental-analyze`.
- Шрифты в preload — ≤ 3 файлов (B11).
- Обложка в preload — ≤ 60 КБ (WebP, 480 px).
- Тест: CPU throttling 6× в DevTools плюс реальный дешёвый Android.

Прогресс чтения — `animation-timeline: scroll()`. Это 0 КБ JS; поддерживается в Chrome и в Safari 26+ ([WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0)). В Firefox полоски просто не будет.

## B11. Шрифты

- `next/font/google`: самостоятельный хостинг, браузер не ходит к Google. Это важно для РФ.
- **Аудит текущего `fonts.ts`:** 5 семейств, у Lora и Literata есть курсив, у Literata ось `opsz`. С preload сейчас Lora (обычный + курсив), Literata (обычный + курсив) и Onest — каждое с подмножествами `cyrillic` и `latin`. Это порядка **8–10 файлов preload**, ~300–400 КБ до LCP (оценка, проверить во вкладке Network).
- Рекомендация:
  - preload только Literata обычный (текст) и Onest (интерфейс);
  - курсивы и Lora — отдельными загрузчиками с `preload: false`;
  - PT Serif и IBM Plex Mono — уже `preload: false`, хорошо.

- Типографика текста: `hyphens: auto` при `lang="ru"`, `text-wrap: pretty` для абзацев, `font-variant-numeric: oldstyle-nums` в тексте. «Ёлочки» и неразрывные пробелы — через `typograf` на сборке.

## B12. Картинки — отдельное предупреждение

- Сейчас в `next.config.ts`: `formats: ['image/avif','image/webp']`, `qualities: [75, 90]` и `minimumCacheTTL` по умолчанию — 4 часа.
- На Hobby **5000 трансформаций в месяц**. Каждый MISS и STALE считается заново ([Image Optimization pricing](https://vercel.com/docs/image-optimization/limits-and-pricing)). 30 обложек × 3 ширины × 2 формата × 2 качества × обновление каждые 4 часа — это десятки тысяч трансформаций в месяц.
- **После превышения новые картинки получают 402**, и вместо обложки дня показывается alt-текст. Ровно в момент ритуала.
- **Решение:** скрипт `scripts/covers.mjs` (sharp) нарезает обложки заранее — WebP, ширины 480 и 960, качество ~80 (AVIF по желанию). Файлы кладутся в `public/covers/<slug>/` с immutable-кешем (заголовок уже настроен). В разметке — `<Image unoptimized …>` или `<img srcset>`. Заодно это переносимо на любой хостинг.
- Если всё же оставлять оптимизацию: `minimumCacheTTL: 2678400` (31 день), один формат, одно качество, урезанные `deviceSizes`.
- Объём репозитория: ~365 обложек × 2 ширины × ~100 КБ ≈ 70–110 МБ в год. Терпимо. Через год — вынести архивные обложки в Blob (1 ГБ на Hobby, но всего 10 ГБ трафика в месяц — поэтому только архив).

## B15. Риски

| Риск | Вероятность | Влияние | Что делать |
|---|---|---|---|
| **Vercel не открывается с мобильного интернета РФ** (блок IP, особенно на своих доменах) ([Хабр Q&A](https://qna.habr.com/q/1405648), [Хабр](https://habr.com/ru/articles/1028136/), [Vercel Community](https://community.vercel.com/t/request-to-change-ip-range-edge-region-due-to-regional-ip-blocking/26269)) | Высокая | Критическое | Проверить в первый час после деплоя. План Б: та же сборка на российском Node-хостинге (Timeweb Cloud: VPS или Apps; `next build && next start`, Node 24, ISR работает на файловом кеше одного инстанса), реакции — тот же Upstash по HTTPS. 1–2 часа. **Cloudflare перед Vercel не поможет**: его в РФ режут на 16 КБ ([Медиазона](https://zona.media/news/2025/06/27/cf-confirmed), [Код Дурова](https://kod.ru/cloudflare-obiasnil-problemi-s-dostupom)) |
| Лимит 1 млн CDN-запросов в месяц на Hobby | Средняя при успехе в ВК | Сайт встанет до конца окна | Мало файлов на страницу (шрифты, чанки), immutable-кеш, SW с precache. Алерт на 70%. Решение заранее: Pro ($20/мес) или переезд |
| Лимит 5000 трансформаций картинок | Высокая при текущем конфиге | Обложки не грузятся | Предварительная нарезка (B12) |
| Пауза Web Analytics после 50 тыс. событий | Средняя | Слепое пятно на неделю | Свои агрегаты в Redis — это ещё и основной источник продуктовых метрик |
| Upstash не подключён к утру | Средняя | Нет общих реакций | Режим «только локально» без ошибок. Владелец подключает за 2 минуты |
| Vercel MCP без доступа к scope команды | Есть уже сейчас | Агенты не могут создать проект | Работать без `teamId` или переавторизоваться |
| ISR отдаёт вчерашнюю главную после полуночи | Высокая (так устроен SWR) | Путаница «какой сегодня» | `DayGuard` + состояние «печатается» + cron-сброс |
| Закешированный 404 для будущего slug | Низкая | Новый рассказ недоступен до часа | Не ссылаться на будущие, cron-сброс, проверка на превью |
| Ошибка Service Worker | Средняя (если делать в спешке) | Пользователи застряли на старой версии | SW — не в первую ночь. Аварийный SW, снимающий регистрацию |
| 3D «сплющивается» в Safari / рывки на Android | Средняя | Ритуал выглядит дёшево | Правила из B6, тест на реальных устройствах, фолбэк 2D |
| Hobby — только некоммерческое использование ([fair use](https://vercel.com/docs/limits/fair-use-guidelines)) | Низкая сейчас | Блокировка при монетизации | Донаты разрешены. Реклама или подписка → Pro или свой хостинг |
| ПДн: почта, Метрика без согласия | Средняя, если торопиться | Штрафы РКН | В MVP никаких ПДн: реакции анонимны, IP не храним. Почта — только через российский сервис рассылок |
| Права на тексты | Средняя | Претензии и удаление | Реестр прав, валидатор годов в `check-content.mjs`, только PD и свои переводы |
| Свежий major Motion 14.0.0 (4 дня) | Низкая | Мелкие баги | Зафиксировать точную версию `14.0.0` (без `^`) до запуска |

## B16. Что нужно от владельца (утром, ~15 минут)

1. Vercel: Storage → Upstash for Redis → бесплатный тариф (если есть; иначе Pay As You Go) → подключить к проекту FantPub.
2. Vercel: если проект не создался — импортировать репозиторий. Включить Web Analytics и Speed Insights.
3. Проверить сайт с мобильного интернета (свой оператор) и попросить 2–3 человек с другими операторами.
4. Проверить превью ссылки в ВК (сообщение самому себе).
5. Решить: Яндекс Метрика (нужен аккаунт и баннер согласия) — да или нет.
6. Домен: нужен ли свой (`.ru` у российского регистратора) или пока `*.vercel.app`, который, по сообщениям, открывается в РФ лучше своих доменов.
7. Подтвердить сайт в Яндекс Вебмастере и Google Search Console.
